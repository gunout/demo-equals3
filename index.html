Comment un simple == au lieu de === peut compromettre une authentification MD5. Démonstration interactive, 100 % locale.

🐘 PHP < 8.0 ⚠️ type juggling 🛡️ hash_equals 📍 100% local

1. Le principe du type juggling

En PHP, l'opérateur == (loose) effectue des conversions de type implicites avant de comparer. Quand deux chaînes ressemblent à des nombres, PHP les convertit silencieusement en nombres.

Avec les hashs MD5, si un hash commence par 0e suivi uniquement de chiffres (ex. 0e462097...), PHP l'interprète comme 0 × 10462097... = 0.

Deux hashs MD5 différents mais tous deux « magiques » deviennent donc « égaux » en ==.

PHP 8.0+ a corrigé ce comportement. Depuis la RFC « Saner string to number comparisons », deux chaînes numériques sont comparées caractère par caractère.

        5. La correction en PHP 8.0+
    

    
La RFC « Saner string to number comparisons » (PHP 8.0, novembre 2020) a modifié == :

    

        

            
PHP 7.4 et antérieur

            
// Chaînes numériques → nombres
"0e4620..." == "0e8304..."
// → 0 == 0 → true ❌

"1" == "01"
// → 1 == 1 → true ❌

"abc" == 0
// → 0 == 0 → true ❌

        

        

            
PHP 8.0 et supérieur

            
// Chaînes numériques → chaînes
"0e4620..." == "0e8304..."
// → false ✅

"1" == "01"
// → false ✅

"abc" == 0
// → false ✅

        

    

    

        Pourquoi ça ne suffit pas : PHP 8 corrige le type juggling, mais la bonne pratique reste
        hash_equals() ou password_verify() (comparaison en temps constant, résistante aux timing attacks).
    







    

        
        6. Comment se défendre
    

    

        

            
1 Stricter la comparaison

            
// Au lieu de :
if (md5($input) == $stored) { ... }

// Utiliser :
if (md5($input) === $stored) { ... }

            
Bloque le type juggling, mais reste sensible au timing attack.

        

        

            
2 Constant-time

            
// hash_equals : O(n) sans court-circuit
if (hash_equals($stored, md5($input))) { ... }

            
Bloque type juggling + timing attacks. MD5 reste faible.

        

    

    
3 Oublier MD5 pour les mots de passe

    
// Inscription
$stored = password_hash($password, PASSWORD_DEFAULT);

// Login
if (password_verify($input, $stored)) {
    // ✅ hash_equals + bcrypt/argon2 + salt automatique
}

    

        Pourquoi MD5 ne doit jamais servir pour des mots de passe :
        
    
            
  • Conçu pour être rapide → brute force GPU (~25 milliards MD5/s)
    • 
            
  • Pas de salt intégré → rainbow tables
    • 
            
  • Conçu pour l'intégrité, pas pour les secrets
    • 
            
  • bcrypt/argon2 sont des KDF pensés pour ralentir les attaques
    • 
        

    







    

        
        7. Côte à côte : vulnérable vs sûr
    

    

        

            
Vulnérable

            
// login.php — NE PAS UTILISER
$user = $_POST['username'];
$pass = $_POST['password'];
$row  = $db->query("SELECT ...")->fetch();

// ❌ == loose, md5 faible, pas de timing-safe
if (md5($pass) == $row['hash']) {
    $_SESSION['user'] = $user;
}

        

        

            
Sûr

            
// login.php — recommandé
$stmt = $db->prepare("SELECT hash FROM users WHERE user=?");
$stmt->execute([$_POST['username']]);
$row = $stmt->fetch();

// ✅ password_verify (hash_equals + bcrypt/argon2)
if ($row && password_verify($_POST['password'], $row['hash'])) {
    $_SESSION['user'] = $row['user'];
}
